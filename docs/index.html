Two-way sync

    
A real copy, kept the same on both sides.

    
For the folder you work in, rather than the drive you
      browse. The first run is the only one that can overwrite, and it asks
      before it does. When both sides changed the same file you settle it in
      the window — not by finding a .conflict file afterwards.

Encrypted drives

    
The provider stores gibberish.

    
Files are encrypted on this computer before they leave
      it — contents and names alike. You use the drive like any other: mount it,
      or sync a folder with it. What the provider keeps is on the right.

Monti says the part most tools
      leave in the small print: the password is kept on this machine the way
      rclone keeps passwords — obscured, which is reversible by design.
      Encryption protects the copy in the cloud. It does not protect the
      machine holding the key.

  


  
  

    
Built for one desktop

    
And honest about the rest.

    

      

        
Linux first, not third

        
Not the third build of a cross-platform app. The defaults are chosen
          for this desktop, and the tray, the file-manager picker and the
          notifications are the real ones.

      

      

        
No account, no server, no telemetry

        
Monti talks to your clouds, and to rclone.org to fetch the engine.
          That is the entire list. MIT licence, and every package carries
          GitHub build provenance you can verify yourself.

      

      

        
No Flatpak, and why

        
Mounting from a sandbox needs a permission that lets the app run
          anything outside it. An install that looks isolated and is not is
          worse than an AppImage that never claimed to be.

      

    

  


  
  

    
Install it.

    
The script checks FUSE, verifies the download against
      the published checksums and installs into your home directory. No root.

    

      curl -fsSL https://raw.githubusercontent.com/stektus/monti/main/install.sh | bash
    

    
Or take the AppImage,
      .deb or .rpm from the releases page — x86_64 and
      arm64. On Arch, build the PKGBUILD in the repository.
