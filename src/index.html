The account password itself, not a recovery key. MEGA has no app passwords: if your account uses two-factor authentication, rclone cannot sign in to it.

The account password. Proton's two-password mode, where the mailbox has a second one, is not supported.

The code is used once, right now — press Connect while it is still valid. After that Proton signs Monti in on its own.

Not the password you sign in with: Koofr wants a password made for apps, at Preferences → Password. Two-factor accounts work this way, and the password can be revoked on its own.

Made on the security page of your account — jottacloud.com → Security → Generate personal login token. It is used once, to sign this computer in; after that Jottacloud keeps Monti signed in itself.

The console does not hand you this one — you chose it there yourself, and it is what the console asks for before it will show your files. Storj never receives it, because files are encrypted on this computer: nobody can look it up or reset it, so written down somewhere safe it is the only copy that matters. Nor is it checked when you connect — another phrase is accepted just as readily and opens an empty drive, because the file names are encrypted too.

Both come from the Storj console. An access grant is the shorter route, because it already carries the encryption passphrase — the key the files are encrypted with, and the only thing that can make them readable again.

Both come from Application Keys in your Backblaze account — create a key, and copy the two values it shows once. A key made for one bucket only sees that bucket.

Files are encrypted on this computer before they leave it, so the provider stores gibberish — file contents and names alike. You use the encrypted drive like any other: mount it, or sync a folder with it.

There is no way to recover this password. Lose it and the files stay encrypted forever — nobody, including you, can read them.

The password is kept in rclone's config file on this computer, scrambled but not protected: anyone who can read that file can recover it. What encryption protects is the copy in the cloud.

Use my own API key recommended for Google Drive

Google is retiring the shared key all rclone apps use — your own free key avoids that and removes speed limits. Takes ~5 minutes, one time:

  1. Create a project in Google Cloud (any name).
  2. Enable the Google Drive API for it.
  3. Configure the consent screen: choose External.
  4. Add yourself as a test user (Audience → Test users → your own e-mail). Skipping this is the #1 mistake — Google will refuse to sign you in with “403 access_denied”.
  5. Create credentials → OAuth client ID → type “Desktop app”.
  6. Copy the Client ID and Client secret below.

During sign-in Google will warn “Google hasn’t verified this app” — that's expected for a personal key: click Advanced → Go to … (unsafe) and continue.

Your browser will open — sign in and allow access. Monti never sees your password; the access token is stored locally by rclone.
